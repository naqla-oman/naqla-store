# منصة نقلة للمتاجر الإلكترونية — Naqla Store Platform

منصة متاجر عُمانية مبنية على **Medusa v2.21** (الخلفية ولوحة التحكم) و**Next.js 15** (واجهة المتجر)، بالعربية من اليمين لليسار.

**الكود واحد لكل العملاء.** كل ما يخص العميل في مجلده `clients/<slug>/`، ويُختار بمتغير واحد `STORE=<slug>`. إنشاء متجر أو ديمو جديد لا يحتاج أي تعديل في الكود.

```
clients/
  _template/        قالب محايد يُنسخ لكل عميل جديد
  <slug>/
    store.json      كل إعدادات المتجر وبياناته (انظر «مرجع store.json»)
    theme.css       الألوان فقط — نهاري وليلي
    logo.svg        الشعار (مربع الهوية بألوانه)
    icons/          icon-192.png و icon-512.png
    og.jpg          صورة المشاركة 1600×900
    images/         صور الواجهة والمنتجات
apps/backend        Medusa — يقرأ clients/$STORE/store.json
apps/storefront     Next.js — يقرأ العميل عبر الاسم المستعار @client
scripts/            أوامر store:new و store:setup و store:dev
.stores/            بيئة كل متجر محلياً (أسرار — خارج Git)
```

---

## المتطلبات

- Node.js 20+ و pnpm 10
- PostgreSQL 16 و Redis 7
- `apps/backend/.env` منسوخ من `.env.template`، ويكفي فيه `DATABASE_URL` صالح (يُستخدم خادمه ومستخدمه لإنشاء قاعدة كل متجر)
- `apps/storefront/.env.local` منسوخ من `.env.template`

```bash
pnpm install
```

## إنشاء متجر جديد — خطوة بخطوة

### 1) نسخ القالب

```bash
pnpm store:new <slug>          # مثال: pnpm store:new demo-perfume
```

يُنشئ `clients/<slug>/` من القالب المحايد. القالب متجر صالح للتشغيل فوراً: منتج تجريبي واحد، والمزايا الخاصة بالأزياء مُطفأة.

### 2) تعبئة `store.json`

| القسم | ما يحدده |
|---|---|
| `name`، `nameEn`، `shortName`، `tagline`، `description` | الاسم والوصف في الواجهة ومحركات البحث |
| `orderPrefix` | بادئة رقم الطلب (مثال `AB-` → `AB-0001`) |
| `freeShippingOver`، `cutoffHour` | حد التوصيل المجاني، وآخر ساعة لطلبات اليوم |
| `fonts.display`، `fonts.body` | الخطان من القائمة الجاهزة في `apps/storefront/src/fonts/presets.json` |
| `colors.theme`، `colors.background` | لون شريط المتصفح وخلفية تطبيق الجوال (الألوان الكاملة في `theme.css`) |
| `contact`، `social` | واتساب، الهاتف، البريد، العنوان، الساعات، الحسابات |
| `nav`، `ticker`، `welcomeCode` | القائمة، الشريط المتحرك، كود الخصم الترحيبي (أو `null`) |
| `home` | الواجهة الرئيسية: `hero`، `tiles`، `trust`، `collectionsOrder` |
| `features` | مفاتيح تشغيل المزايا (انظر الجدول التالي) |
| `options` | خيارات المنتج لنشاط العميل ونوع منتقيها |
| `loyalty` | النقاط لكل ريال، الاستبدال، والمستويات وامتيازاتها |
| `checkout`، `product` | المحافظات، الهاتف، نصوص التوصيل والهدية، مزايا صفحة المنتج، جداول المقاسات |
| `location`، `shipping`، `promotions` | المحل، طرق التوصيل وأسعارها، أكواد الخصم |
| `categories`، `collections`، `tags`، `products` | الكتالوج |

**مفاتيح التشغيل** في `features`. ما يُطفأ يختفي من الواجهة كلياً، ولا تُنشئه الخلفية:

| المفتاح | الميزة |
|---|---|
| `tailoring` | أزرار التفصيل الخاص وحجز القياس (لأقسام `product.atelier.categories`) |
| `sizeGuide` | دليل المقاسات (جداول `product.sizeGuides` لكل قسم) |
| `lengthField` | حقل «طولك بالسنتيمتر» (لأقسام `product.lengthField.categories`) |
| `gift` | خيار «هذه هدية» مع رسالة البطاقة |
| `expressDelivery` | التوصيل السريع (طريقة `express` في `shipping`) |
| `pickup` | الاستلام من المحل (طريقة `pickup`) |
| `loyalty`، `loyaltyTiers` | نقاط الولاء، ومستوياتها مع مجموعات العملاء وامتيازاتها |
| `cod`، `whatsappOrder`، `thawani` | طرق الدفع (ثواني يتطلب أيضاً `THAWANI_ENABLED=true` في الخلفية) |
| `bnpl` | التقسيط (يبقى مُطفأً حتى يُربط مزوّده) |

**خيارات المنتج** تُعرَّف مرة واحدة لكل نشاط في `options`، وكل منتج يذكر قيمها:

```json
"options": [
  { "key": "size",  "title": "المقاس", "type": "buttons" },
  { "key": "color", "title": "اللون",  "type": "color",
    "swatches": { "أسود": ["#1c1f1e", "#3b3f3d"] } }
]
```

- `type: "color"` يُعرض كدوائر ألوان من `swatches`. أي نوع آخر يُعرض كأزرار.
- أمثلة: المقاس واللون للأزياء، الحجم للعطور، الوزن والنكهة للحلويات.
- كل منتج يذكر قيمه في `"options": { "size": ["S","M"], "color": ["أسود"] }`، وتُنشأ كل التركيبات كمتغيّرات.
- السعر والمخزون حسب قيمة **الخيار الأول**: `"prices": { "50 مل": 18, "100 مل": 29 }` و`"stock": { "50 مل": 12 }`. وبدونها يُستخدم `price` والمخزون الافتراضي 10.
- ترتيب القيم في الواجهة هو ترتيبها في `store.json`.

### 3) الهوية

- **`theme.css`:** عدّلي قيم الرموز فقط، نهاري ثم ليلي، وكل الرموز مطلوبة. الواجهة لا تحوي أي لون مكتوب مباشرة.
- **الملفات:** `logo.svg`، و`icons/icon-192.png` و`icon-512.png`، و`og.jpg`.
- **الصور:** في `images/`، ويُشار إليها من `store.json` بمسار نسبي مثل `images/hero.jpg`.

### 3ب) نقل كتالوج من متجر سابق (اختياري)

عميل لديه متجر قائم (شوبيفاي، سلة…) وجدول منتجاته بصيغة xlsx:

```bash
# 1) قواعد الاستيراد في clients/<slug>/import.json: أسماء الأعمدة، قواعد الأقسام، توحيد البراندات، خيار العبوة
# 2) تنزيل الصور وبناء الكتالوج (أعيديه حتى «لم تُنزَّل» = 0؛ يتخطى الموجود)
pnpm store:import <slug> <file.xlsx> --images            # --limit 100 لمتجر تجريبي؛ خلف وكيل: NODE_USE_ENV_PROXY=1
# 3) ثم الإعداد كالمعتاد
pnpm store:setup <slug>
```

- الناتج `clients/<slug>/catalog.json` (المنتجات، والبراندات كمجموعات) — يقرؤه الخادم وحده ويُدمج فوق `store.json`؛ لا يدخل حزمة الواجهة.
- الأقسام نفسها تُعرّف في `store.json → categories`، والمستورد يوزّع عليها: قواعد العنوان أولاً (واقي شمس، عدسات…)، ثم تصنيف المصدر، ثم كلمات العنوان، ثم `fallbackCategory`. التقرير يطبع عدد كل قسم وما لم تطابقه قاعدة.
- الروابط (`handle`) تبقى كما في المتجر السابق، فتُحوَّل روابطه القديمة بسطر واحد في الخادم.
- مع مئات البراندات: `home.collectionsMax` يحدد عدد صفوف المجموعات في الرئيسية، و`home.collectionsOrder` ترتيبها.

### 4) الإعداد

```bash
pnpm store:setup <slug>
```

ينفّذ:
1. يُنشئ قاعدة جديدة `naqla_<slug>`.
2. يشغّل الترحيلات والبذرة كاملة: المنتجات، الدفع، التوصيل، الضريبة، رفع الصور إلى Medusa، المستويات.
3. يُنشئ مستخدم أدمن بكلمة مرور عشوائية.
4. يحفظ بيئة المتجر في `.stores/<slug>.env`، ويختار له منفذين غير مستخدمين (9000/8000، 9001/8001…).

لإعادة الإعداد على قاعدة جديدة: `pnpm store:setup <slug> --force` بعد حذف القاعدة القديمة.

### 5) التشغيل

```bash
pnpm store:dev <slug>
```

يشغّل الخلفية والواجهة بمنفذي المتجر وقاعدته. يمكن تشغيل أكثر من متجر في الوقت نفسه من الكود نفسه، كلٌّ في طرفية:

```bash
pnpm store:dev <slug-1>     # المتجر http://localhost:8000 — اللوحة http://localhost:9000/app
pnpm store:dev <slug-2>     # المتجر http://localhost:8001 — اللوحة http://localhost:9001/app
```

بيانات دخول الأدمن في `.stores/<slug>.env`.

## كيف يعمل الفصل

- **الخلفية:** `apps/backend/src/lib/client.ts` يقرأ `clients/$STORE/store.json`. بلا `STORE` يتوقف الخادم والبذرة برسالة واضحة، فلا توجد قيمة افتراضية.
- **الواجهة:** `next.config.js` يقرأ `STORE` ويعرّف أسماء مستعارة:
  - `@client` ← مجلد العميل، ومنه `store.json` و`theme.css`.
  - `@client-font-display` و`@client-font-body` ← ملفا الخطين المختارين.
  - لا تُنسخ ملفات العميل، ولهذا يعمل متجران من الكود نفسه.
- **ملفات العميل:** صوره وأيقوناته وشعاره وصورة المشاركة تُقدَّم من `/client-assets/...`. يُقدَّم فقط `images/` و`icons/` و`logo.svg` و`og.jpg`، ولا يُقدَّم `store.json`.
- **صور المنتجات:** تُرفع عند الإعداد إلى وحدة الملفات في Medusa، في `static/<slug>/` لكل متجر، فتظهر في لوحة التحكم.
- **`store.config.ts`:** يحوّل `store.json` إلى الشكل الذي تستخدمه الواجهة، ويطبّق مفاتيح التشغيل في مكان واحد.
- **مجلد البناء:** لكل متجر مجلد بناء حسب منفذه (`NEXT_DIST_DIR=.next-<port>`)، فلا يتصادم متجران.

## الإنتاج: البناء والمسارات والأسرار

- **المسارات ثابتة** (لا `process.cwd()`): الجذر `NAQLA_ROOT` يُكتشف من `pnpm-workspace.yaml` أو يُضبط صراحة في الحاوية. منه: `.env` الخادم، و`clients/` (أو `CLIENTS_DIR`)، و`admin-brand/`، و`package.json` (إصدار نقلة).
- **الصور المرفوعة** في `UPLOADS_DIR` (افتراضياً `apps/backend/static`) خارج `.medusa` — في الإنتاج volume دائم. البناء لا يحذفها.
- **البناء**: `pnpm --filter @naqla/backend build` = `medusa build` ثم `scripts/backend-postbuild.mjs` (ينسخ `admin-brand` ويربط `.medusa/server/static` بمجلد الصور، لأن Medusa يقدّم `/static` من مجلد التشغيل دون إعداد).
- **التشغيل**: من `apps/backend/.medusa/server` بـ `medusa start` مع بيئة المتجر و`NODE_ENV=production`.
- **الأسرار**: `pnpm store:setup <slug>` يولّد `JWT_SECRET` و`COOKIE_SECRET` (48 بايت لكل متجر). الإنتاج يرفض الإقلاع بسر فارغ أو ضعيف.
- **Redis**: عند ضبط `REDIS_URL` يجب أن يكون متاحاً. في الإنتاج يتوقف الإقلاع بخطأ واضح إن لم يتوفر (يعيد Docker التشغيل)، وفي التطوير تحذير فقط — وللتطوير بلا Redis احذف `REDIS_URL` فتعمل الوحدات في الذاكرة. الجاهزية الحقيقية من `/ready` (قاعدة البيانات + Redis)؛ `/health` المدمج يبقى «OK» حتى مع انقطاع Redis فلا يُعتمد عليه.
- **رموز الدخول (OTP)**: قفل لكل رقم، وسقف يومي لكل رقم، وحدود لكل IP في الساعة. خلف Caddy: عنوان العميل يُقرأ من آخر قيمة في `X-Forwarded-For`.

## النشر على خادم (Docker + Caddy)

الملفات في `deploy/`: `backend.Dockerfile`، `storefront.Dockerfile`، `docker-compose.yml`، `Caddyfile`.

1. على الخادم: انسخي المستودع، وأنشئي `deploy/.env` فيه `POSTGRES_PASSWORD` و`ACME_EMAIL` ومعرّفات كل متجر `STORE1_SLUG` و`STORE1_DOMAIN` و`STORE1_PUBLISHABLE_KEY`.
2. بيئة كل متجر في `.stores/<slug>.prod.env` (صلاحيات 600): الأسرار من `store:setup`، و`DATABASE_URL` على `postgres`، والنطاقات الحقيقية في CORS و`MEDUSA_BACKEND_URL` و`STOREFRONT_URL`، و`NODE_ENV=production`.
3. `docker compose -f deploy/docker-compose.yml up -d --build`.

- الخلفية لا تقلع قبل جاهزية Postgres وRedis (`depends_on … service_healthy`)، وتتوقف بخطأ واضح إن لم يتوفر Redis، وصحتها من `/ready`.
- الصور في volume دائم (`/data/uploads`) يُربط بـ `static` عند كل تشغيل؛ والترحيلات تعمل تلقائياً قبل الخادم.
- Caddy: HTTPS تلقائي، HSTS، منع تضمين اللوحة (`/app`) في إطار، حذف `X-Powered-By`، وسجلات بلا `otp` ولا التوكنات والكوكيز.
- متجر جديد = نسخ كتلتي `backend-<slug>`/`storefront-<slug>` في compose وكتلتي النطاقين في Caddyfile.

## اختبار ثواني (UAT)

- فعّلي في `.stores/<slug>.env`: `THAWANI_ENABLED=true` و`THAWANI_MODE=uat` ومفتاحي UAT العامين (في `apps/backend/.env.template`)، واربطي `pp_thawani_thawani` بالمنطقة من اللوحة (الإعدادات ← المناطق) إن لم يكن مرتبطاً.
- بطاقة الاختبار: `4242 4242 4242 4242`، الانتهاء أي تاريخ قادم، CVV `123`، ثم رمز التحقق (OTP) `1234` ← «Verify & Pay».
- حقول صفحة ثواني بقناع إدخال: تُكتب حرفاً حرفاً (لصق التاريخ دفعة واحدة يُرفض بـ «Please complete the Date»).
- بعد الدفع تعود الزبونة إلى `/checkout/thawani?cart_id=…` فيُنشأ الطلب، والدفعة «captured» بفاتورة ثواني ومبلغ مطابق.

## قبل إطلاق أي عميل حقيقي

- `features.reviews` يبقى **false** (هو كذلك في القالب): التقييمات المعروضة في الديموهين أرقام مزروعة للعرض فقط، وإظهارها لعميل حقيقي تضليل ومخالف لإرشادات Google — حتى يُبنى نظام تقييمات حقيقي.
- `merchantPhones`: رقم/أرقام التاجر الشخصية لتنبيه «طلب جديد» على واتساب.
- قوالب واتساب السبعة معتمدة من Meta ومربوطة (صفحة «قوالب واتساب» في اللوحة تعرض الحالة).
- صفحات السياسات (`clients/<slug>/pages/` أو مسودات القالب) مراجعة بالسجل التجاري والسياسات الفعلية.
- `deliveryOffDays` و`cutoffHour` مطابقان لأيام وساعات المتجر الفعلية.

## ملاحظات تقنية

- **فحص الخلفية:** `medusa develop` يشغّل `medusa lint` قبل البدء ويرفض التشغيل عند أي خطأ. شغّلي `pnpm --filter @naqla/backend lint` قبل كل commit.
- **ترتيب سكربتات الترحيل:** تعمل أبجدياً، مرة واحدة لكل قاعدة:
  1. `initial-data-seed`
  2. `seed-02-checkout-setup`: الدفع، والتوصيل المقيّد بمحافظات، والأكواد.
  3. `seed-03-tax-inclusive-shipping`
  4. `seed-04-product-images`
  5. `seed-05-loyalty-tiers`
- **رموز المحافظات:** في `checkout.governorates` (ISO 3166-2:OM)، ويجب أن تطابق `shipping[].provinces`.
- **خيارات Medusa v2.21 مشتركة بين كل المنتجات:** لذلك تُستخرج قيم كل منتج من متغيّراته في `modules/products/lib/variants.ts`، ويُحفظ ترتيبها في `metadata.option_order`.
- **رمز واتساب والإشعارات:** بدون `WHATSAPP_ENABLED=true` تُكتب في سجل الخادم أثناء التطوير فقط، ويُرفض الدخول في الإنتاج. نصوص القوالب لكل عميل في مجلده.
- **إيقاف Medusa في السكربتات:** استخدمي `pkill -f "[m]edusa develop"` في أمر منفصل عن إعادة التشغيل.
